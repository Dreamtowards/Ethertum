# Ethertia 代码审查与重构执行计划

审查日期：2026-10-20。依据：当前工作树源码、Cargo manifest、锁文件及已有文档。用途：让普通能力的 Agent 按任务编号逐项执行，避免一次性重写整个项目。

本轮只新增此文档，不修改运行时代码、依赖、锁文件，不提交或推送。开始审查时工作树干净。用户随后要求优先读代码、不再运行 Cargo；后续分析与计划均按此要求进行。

## 1. 审查结论

项目已有可保留的基础：客户端/服务器目录边界、不可变区块快照、写时复制、网格任务修订号与世界 epoch、网络解码边界，以及针对异常包和区块生命周期的测试。主要欠缺是**统一的世界权威来源、完整的会话生命周期和持久化闭环**。

建议顺序：小范围正确性修复 → 明确生命周期和预算 → 服务端权威区块 → 编辑同步 → 持久化 → 真实世界列表 → 模块与平台整理。

- `src/lib.rs:1` 已启用 `deny(invalid_reference_casting)`；`Chunk::at_voxel_mut` 要求可变借用，使用 `Arc::make_mut`，旧的 `AsMutRef` 问题已经修复。
- `src/voxel/voxel_client.rs:714`、`:722` 已拒绝过期生成/网格结果；`:130` 已取消客户端世界任务并清理 channel。
- `src/net/validation.rs:15` 已限制消息大小、校验字段并处理命令错误；登录分支已经移除模拟 sleep 和 token 日志。

`docs/REVIEW.md`、`docs/UPGRADE.md` 是历史记录，部分行号和未完成状态已过时。不要直接复制历史问题作为当前事实，也不要把升级 Bevy 当成本计划前置条件。

### 需要测量后再决定的优化

- 队列长度、每帧扫描/收包/上传数量、任务耗时、网格与碰撞体构建耗时、帧时间分位数。
- `get_voxel_mut` 每次借用即增加相关修订号；笔刷批量编辑和光照传播可能重复失效。先统计，再引入编辑事务合并。
- 快照仍克隆 Chunk 的渲染句柄并分配邻居 Box；线程局部顶点缓冲保留峰值容量。先测内存，不因“有分配”就重写。
- 当前所有应用消息使用 ReliableOrdered；区块数据与位置消息共用通道可能互相排队。分通道前先定义版本、序号和过期消息处理。
- 不以本轮静态审查声称 shader、碰撞或视觉质量已通过运行时验证。

## 3. 目标边界与固定决策

1. **单人也使用内置服务器拥有世界数据。** 远程客户端和单人客户端复用同一套区块/编辑协议，客户端只持有表现缓存。离线预览若保留，必须显式选择，不能在网络缺数据时偷偷生成替代区块。
2. **保留现有快照和修订号机制。** 网格修订号、服务器区块数据版本、存盘修订号是不同概念，分别命名，不混用。
3. **先在现有 crate 内分模块。** 暂不拆多个 workspace crate，不引入通用框架、不升级 Bevy。
4. **先完成桌面闭环。** DDGI、Web、Android、iOS 独立记录和验收，不与核心重构混在同一个任务中。
5. **网络原型继续明确为未认证。** 本计划不把 UUID、token 字段、用户名或合法报文视为认证/权限证明；正式认证是后续独立项目。

建议逐步形成的职责：

| 层 | 拥有的数据/职责 | 不应承担 |
| --- | --- | --- |
| `voxel` 数据与生成 | 体素、坐标、只读快照、世界生成参数 | UI、传输、材质句柄的业务决策 |
| `server` 世界服务 | 区块数据、加载需求、编辑判定、世界时间、保存状态 | 客户端网格和 UI |
| `net` | 编解码、连接状态、消息预算、协议版本 | 在包处理 match 内实现全部世界业务 |
| 客户端区块缓存 | 数据版本、网格任务、网格/碰撞体安装 | 自行决定联网世界内容 |
| `client` 会话 | 连接、入场、退出、错误、取消请求 | 通过任意删除 Resource 隐式触发所有流程 |
| UI | 展示状态、发出用户意图 | 阻塞 I/O、直接改服务端世界、跨系统 static mut |

现有 Chunk 同时携带体素和渲染句柄。仅在后面的结构整理任务中渐进拆成数据与表现，不要在修复一处 bug 时顺手迁移所有调用方。

## 4. Agent 执行规则

- 一次执行一个任务卡；一个任务产生一个可独立审查的 diff。任务编号不是自动提交指令。
- 开始先读 `AGENTS.md`，运行 `git status --short`，阅读任务指定文件；以当前代码确认问题是否仍存在。
- 只修改本卡范围和必要的直接调用方。跨协议的变更必须同时修改两端，明确 `PROTOCOL_ID` 和 bincode 枚举兼容性。
- 每次交付说明：修改文件、行为变化、验收依据、未验证项、下个可执行任务；更新此文档中任务状态。
- 用户当前要求不跑 Cargo：执行时优先遵守最新会话约束；这里列出的测试是未来验收要求，本轮不再执行。不能写“未运行但通过”。
- 行为任务需要有针对性回归；不为了小型文档或机械搬移新增镜像实现的测试。不运行全仓格式化、`cargo fix`、升级依赖或改锁文件。
- 缺少图形或双客户端运行条件时记录未验证，不用编译通过替代行为/视觉验收。
- 遇到依赖任务未完成，只做本卡允许的前置接口/文档，不自行扩大范围。没有授权时不提交、推送、发布。

### T06 移除 UI 阻塞请求（F05）

- **依赖/范围**：T01；`src/client/ui/serverlist.rs`、`src/client/game_client.rs`、`src/util/mod.rs`，允许新增客户端请求模块。
- **实施**：把列表拉取、状态刷新、DNS 解析统一交给有并发上限的后台 I/O 执行器；主循环只发请求和轮询完成消息。为每项请求记录 ID；取消、切换页面、删除/修改服务器条目后拒绝旧结果。
- **默认预算**：并发最多 4；HTTP 连接超时 3 秒、总超时 5 秒、响应体最多 1 MiB；作为可命名常量。DNS 的迟到结果必须可忽略，不能假定丢弃句柄能中断系统解析调用。
- **验收**：慢响应、超时、错误 JSON、超大响应、取消后完成、编辑地址后旧结果到达均不阻塞/覆盖当前 UI。错误包含可读原因，连接失败填充断线原因。
- **边界**：沿用已安装的库；不要为了 async 引入整套运行时或再次升级依赖。

### T07 显式管理客户端与内置服务器会话（F07）

- **依赖/范围**：T02、T06；`src/client/game_client.rs`、`client_world.rs`、`src/server/integrated_server.rs`、两端任务资源。
- **实施**：引入一个明确的 SessionState：Menu、Connecting、Playing、Leaving，并区分 Integrated 与 Remote 模式；统一连接成功、失败、主动退出、远端断线路径。内置服务系统只在 Integrated 会话运行，菜单和 Remote 会话不绑定/保留多余服务端会话。
- **任务生命周期**：服务端加载任务跟踪从 Local 移入会话资源；增加 epoch/请求 ID/取消标识，换世界后拒绝旧结果；清理服务端玩家、区块实体、传输和 channels。退出过程不能阻塞主循环。
- **验收**：连接失败、连接时取消、连续退出、同名重入、内置→远程→内置切换无残留实体/端口；旧世界结果不能安装到新世界；保留菜单相机。
- **拆分方式**：先提交会话状态与统一入口的 diff，再提交服务端任务清理的 diff；两步保持当前可进入世界，不同时迁移所有 UI 框架。

### T08 给加载和收包设置预算（F06）

- **依赖/范围**：T03、T07；`src/util/mod.rs`、`src/voxel/voxel_server.rs`、`voxel_client.rs`、`src/net/netproc_server.rs`。
- **实施**：把中心扩散改成能提前停止的迭代器；先修正 `>` 边界。维护去重的待生成/待发送队列；玩家跨区块或改变距离才更新需求，脱离需求的任务结果不安装。按轮转方式处理玩家，避免固定顺序饿死后面的玩家。
- **预算**：生成并发、扫描候选数、每帧安装/上传数、每玩家发包字节和收包条数均为独立限制；例如首轮总生成并发 8、每玩家每帧最多发 4 个区块，收包每玩家每帧最多 64 条，并设全局预算。余量留到下一帧，不丢可靠编辑消息。
- **验收**：队列满时遍历会实际停止；最大合法距离、多个玩家、移动/禁用/断线后队列不无限累积；持续发包客户端不独占一帧；计数可观测。性能提升仅在测量后报告。

### T09 清除跨系统 static mut（F10）

- **依赖/范围**：T07；`src/client/ui/mod.rs`、`src/client/input.rs`、`src/client/character_controller.rs` 和 UI helper 的直接调用方。
- **实施**：窗口尺寸从窗口/egui context 取得；音效与返回意图使用 Resource/消息；双击和跳跃计时归到对应控制器组件。明确 UI 输入、角色输入和 UI 意图消费顺序。
- **验收**：这些文件不再含运行中的 static mut；两个控制器计时不互相干扰；退出重进不会复用上次计时；返回、缩放、点击、双击飞行/冲刺和跳跃行为保持。核对一次性 UI 音效播放结束后的实体清理。

### T10 统一世界配置与服务端完整生成（F01、F11）

- **依赖/范围**：T07、T08；世界配置类型、`src/voxel/worldgen.rs`、`voxel_server.rs`，必要的区块邻域接口。
- **实施**：新增 WorldConfig，包含 world_id、seed、generator_version；基础生成和 populate 都从配置读取参数。服务端先生成基础邻域，再完成地表/植被填充，完成后才向客户端发布区块。
- **生成约束**：生成所需 halo 不等于客户端订阅距离；树跨区块写入和相邻 populate 顺序必须确定，采用固定坐标顺序及明确写入冲突规则，避免任务完成先后改变世界。只对独立快照/主线程拥有的数据写入。
- **验收**：相同 seed/version 的相同区块在不同请求顺序下结果一致；不同 seed 会变化；负坐标和跨边界树完整；缺失邻居时不会把未完成区块当最终数据发送。
- **边界**：此卡不落盘、不切换普通客户端数据来源；为 T11 提供完整服务端区块。

### T11 切换普通入口到权威区块与订阅差集（F01、F02）

- **依赖/范围**：T08、T10；`src/client/client_world.rs`、`src/net/netproc_client.rs`、客户端/服务端区块系统。
- **实施**：登录成功即发送校验后的加载距离，设置变化后重发；为每个玩家维护 desired/sent 差集，离开订阅范围就发 ChunkDel，即使其他玩家仍需要该块。全局卸载基于所有玩家需求及必要生成 halo。
- **客户端**：联网模式禁用本地基础生成和 populate；ChunkNew 仅安装服务器快照；ChunkDel 复用现有 despawn_chunk 并取消对应请求/拒绝过期网格，删除幂等。显式离线预览模式若保留，使用独立入口。
- **验收**：通过普通桌面入口连接而非测试程序专用设置，能看到服务端生成的地形/植被；两个客户端收到相同数据；一人离开范围时只清掉该人的缓存；删除后无旧碰撞体、后台结果复活或 ChunkDel 占位错误。
- **临时行为**：在 T12 完成前，权威模式禁用本地编辑并清楚提示暂不可编辑；不能继续展示无法同步的修改。

### T12 建立服务端编辑流水线（F02）

- **依赖/范围**：T02、T04、T11；协议、validation、两端包处理、服务端世界编辑与客户端编辑入口。
- **分成三个连续小任务**：① 定义并测试新协议/编解码；② 服务端判定和应用；③ 客户端接入与双端验证。每步同时维护两端可编译性，新功能全部接通前保持禁用。
- **协议**：独立网络实体 ID；EditRequest 带 request_id、预期区块数据版本和受限编辑意图；服务器响应接受/拒绝及最终版本。ChunkNew/Delta 带数据版本，提升 PROTOCOL_ID，拒绝旧协议。不要直接复用旧 bincode 枚举序号而不评估兼容性。
- **服务端**：先校验登录、订阅、距离、操作大小、材质/形状和版本；先验证受影响的所有区块，再原子应用或全部拒绝；写入后递增区块数据版本、标记 dirty，向订阅者广播。当前基于玩家上报位置的距离检查不是反作弊或真实权限校验。
- **客户端**：首版等确认后应用，不实现预测回滚；本地和网络变化都走同一个批量编辑/网格失效入口，每个受影响区块每次事务只递增一次网格修订；网格与碰撞体按同一有效结果更新。
- **验收**：A 编辑后 B 相同；负坐标面/边/角、旧版本、重复 request_id、越权范围、非法材质、未加载区块和断线重试有确定结果；拒绝时不部分改写；旧响应不覆盖新状态。

### T13 定义并实现存档编码（F11）

- **依赖/范围**：T04、T10、T12；新增持久化模块，替换未接入的 chunk_storage 骨架。
- **实施**：版本化 world.json 保存 world_id、seed、generator_version、format_version 和时间；区块文件保存坐标、数据版本及体素数据。首版用每区块独立文件，暂不做 region、压缩或数据库。
- **格式**：不序列化 Entity、Handle、邻居快照或任务状态；定义 Item/材质稳定名称到存储 ID 的表。默认值、字节长度上限、版本拒绝和损坏检测写进格式说明；未知版本不得静默按当前版本读取。
- **验收**：负坐标、空/完整区块、各种体素属性往返一致；截断、错误坐标、过大文件、未知版本返回错误；加载存档区块不再重新 populate 改写内容。

### T14 异步保存、加载优先级与可靠退出（F11、F13）

- **依赖/范围**：T07、T12、T13；服务端世界生命周期、持久化 worker、通用文件替换工具。
- **实施**：读取顺序为“有效存档 → 未找到则生成”；损坏存档报错且保留，不能用新地形覆盖。dirty 数据通过快照进入有界保存队列；临时文件写完后在同目录完成经平台验证的替换，失败保留旧版本及 dirty 状态。
- **修订规则**：保存响应带 world epoch、区块数据版本/保存请求号；只有匹配当前数据版本的成功响应才能清除 dirty。卸载中的 dirty 区块先保留可保存数据，不因 ECS 表现卸载丢失。
- **退出规则**：Leaving 状态等待待保存队列收敛，持续渲染/处理事件；失败提供重试/取消退出，不能把请求入队当作保存完成。替换语义在 Windows 上实际验证，不直接假定覆盖 rename 可用。
- **验收**：保存期间继续编辑、写入失败、旧保存响应、快速切世界、卸载、强制中断后恢复均有确定结果；正常重启恢复最后确认保存的数据。
