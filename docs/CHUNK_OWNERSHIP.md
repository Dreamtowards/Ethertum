# 区块所有权与后台任务

本次修复针对 `REVIEW.md` 中共享引用强转为可变引用的问题，使用当前 Bevy 0.19.1 依赖，不修改网络协议或锁文件。

## 数据所有权

- 客户端和服务端的世界系统持有 `HashMap<IVec3, Chunk>`，不再共享可变 `Arc<Chunk>`。
- `Chunk` 的体素数组使用私有 `Arc<[Vox; 4096]>`。读取可以共享；`at_voxel_mut` 要求 `&mut Chunk`，通过 `Arc::make_mut` 在需要时复制数组。没有后台快照时不会额外复制。
- `ChunkSystem::get_chunk_mut` / `get_voxel_mut` 要求 `&mut self`。客户端在返回可变借用前使受影响网格失效；区块表不能从外部直接修改。
- `ChunkSnapshot` 只提供只读访问，包含中心区块及最多 26 个独立邻接快照。邻接快照共享不可变体素数组，不包含指向运行中世界的弱引用；邻接区块卸载不会改变已经提交给任务的采样数据。
- 地形基础生成在后台独占新 `Chunk`，经 channel 交给主线程。植被填充和树生成在主线程修改独立邻域副本，再安装发生变化的体素数组，不覆盖实体和网格句柄。

## 网格失效与结果安装

网格任务捕获世界实例标识和该区块的网格修订号。修订号涵盖体素、光照、邻接加载/卸载和调试模式等网格输入，不能仅理解为网络版本号。

本地单体素编辑按网格采样的一个体素边界范围，使面、边和角上的全部相关区块失效；负坐标仍按向下对齐到 16 的世界坐标处理。整区块修改和邻接变化保守地使中心及 26 个邻接网格失效。

后台计算网格和碰撞体时只访问快照。结果安装前检查当前世界、任务标识、区块存在性及修订号；拒绝过期结果，并保留最新重建请求。过期任务的完成消息不能清除后来启动的任务。接受结果后，同一次处理更新三种表面和地形碰撞体，继续使用空网格的上传/可见性保护。

本地生成请求另有请求标识。网络区块到达后清除对应生成请求，迟到的本地生成结果不能覆盖已经接收的区块。

退出世界时立即标记取消，移除该世界的任务 channel 与世界系统。旧任务持有的发送端不会连接到新世界；发送失败作为正常退出处理。已开始的有限计算可以收尾，但不能写入世界或安装结果。

## 其他转换调用方

删除 `util::as_mut` / `AsMutRef`，并启用 `deny(invalid_reference_casting)`。物品注册使用 `ResMut` 的正常可变借用；背包 UI 使用 ECS 资源传递物品表与手持物品，移除静态裸指针和静态可变物品引用；WFC 使用索引及独立可能性列表传播约束。

## 验证范围

回归测试覆盖快照隔离、后台读取期间编辑/卸载、面/边/角与负坐标、区块替换、退出后的结果、生成与网络区块竞争、邻接到达、植被写入邻接区块、光照传播和 WFC 借用。`world_smoke --edit` 额外在八个区块的共同角附近放置并移除体素，用真实物理射线确认碰撞体重建，随后验证退出重进。

本次不实现服务端权威地形编辑、持久化或正式认证；两个客户端的本地编辑仍不应被描述为已经同步。实验渲染、Web 和移动端运行时需要各自验证。
